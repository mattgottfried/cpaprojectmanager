# CLAUDE.md

Native SwiftUI + SwiftData practice-management app (CRM + projects + daily task
capture) for a solo CPA's side business. iOS/iPadOS today, Mac Catalyst now, native
macOS later. Syncs through the user's own iCloud (CloudKit); no server.

**Read these first and follow them without being reminded:**
- `docs/PREFERENCES.md` — how to work with the owner (batching, questions, git, comms).
- `docs/DESIGN.md` — the visual language. New screens use it from the start.

## Project-specific answers to PREFERENCES.md placeholders

- **Branch:** work on `claude/awesome-dirac-vpisx9`. Base branch is
  `claude/cpa-project-manager-k5vauq` (no `main` exists yet) — confirm once, then follow.
- **Build/registration:** project is generated by XcodeGen from `project.yml`
  (`.xcodeproj` is git-ignored). New Swift files under `CPAManager/`, `CPAWidgets/`,
  or `CPAManagerTests/` are picked up automatically — never edit `.xcodeproj`.
- **CI:** none. There is no compiler in the cloud session: review every diff by hand
  for Swift footguns before calling it done, and say plainly that it wasn't built.
- **Schema changes:** any new `@Model` or stored property needs a CloudKit schema
  redeploy to Production before the next TestFlight build (see README).
- **Testing on device:** keep a running "what to test" list in the PR/summary.

## Architecture

```
Models/     SwiftData @Model types. Every property has a default; every relationship is
            optional AND has an inverse declared on the other model (CloudKit rules).
Services/   Business logic. Pure/static types (QuickAddParser, NoteDigestParser,
            TodayPlanner, Agenda, WorkflowEngine…) take plain values and are unit-tested;
            thin store-facing types (InboxService, NotificationScheduler…) take a
            ModelContext.
Intents/    App Intents (Siri / Shortcuts / share sheet). They run in the app process
            and use `Persistence.shared.container` — never build a second container.
Views/      SwiftUI. Today, Inbox, Clients, Work, More tabs. Reusable pieces in Components/.
Shared/     Compiled into BOTH app and widget: Theme, Formatters, DateMath, snapshot types.
CPAManagerTests/  XCTest for the pure logic above.
```

### Capture & Today (the daily loop)

- **InboxItem** — anything captured but not yet decided on (source: manual / text /
  email / note / siri). Processed items are kept, not deleted, so their `dedupeKey`
  stops a re-imported note from resurrecting them.
- **TaskItem** can be standalone (no project). `isNextAction` = undated "do next";
  `snoozedUntil` hides it from Today until that day; optional `client`.
- **TodayPlanner** (pure) sorts `PlannerItem`s into Overdue / Today / Next up / Coming
  up and counts snoozed. Deadlines tab keeps the long view.
- **Text & email capture:** iOS/macOS give apps no read access to Messages, Notes, or
  Mail. The owner's texts are digested by Siri into an Apple Note; a Shortcuts
  automation runs Find Notes → Get Text → **Add to Inbox** (App Intent) on a schedule.
  Email uses a share-sheet Shortcut. `NoteDigestParser` splits lines and dedupes so
  re-running is safe. Direct Outlook (Microsoft Graph) sync is a possible later step.

## Rules that already bit us

- Adding a relationship without its inverse → `SwiftDataError` on launch. Declare both.
- Don't nest a `NavigationStack` in something pushed from another stack — views used in
  More take `embedded: true`.
- Semantic colors go through `Theme.color(_: SemanticState)`; never inline a color for a
  state at a call site.
- Undoable actions get an undo toast (`.undoToast`), not a confirmation dialog.
